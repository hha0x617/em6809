# メモリダンプペインの編集機能

本書は、GUI のメモリダンプペイン（Memory）での編集機能の使い方をまとめたものです。

## 概要

- 編集モードで、表示中のメモリを 1 バイト単位で編集できます（Hex セル）。
- 変更は一度ペンディングとして保持され、Apply でエミュレータに反映されます。
- 反映後はリスティングやメモリ表示が自動的に更新されます。

## 操作手順

- 編集モード切替:
  - ペイン上部の「Edit」をクリックすると編集モードに入ります。
  - 編集モードでは「Apply」「Cancel」ボタンが表示されます。
- セル編集:
  - Hex 側の対象セルをクリックするとインライン編集（TextEdit）が有効になります。
  - 入力した値は 16 進として解釈され、ペンディング（未適用）に追加されます。
  - 変更が発生したセルのみ、Hex/ASCII 両側で淡い黄色の背景でハイライトされます（元の値と同じ入力はハイライトされません）。
- Apply/Cancel:
  - Apply: ペンディングをまとめて適用（書き込み）します。適用直後に編集モードは終了します。
  - Cancel: ペンディングを破棄し、編集モードを終了します。

## キーボード操作（編集モード）

- Tab / Shift+Tab: 次／前のセルへ移動。
- Enter: 次のセルへ移動。
- Left / Right:
  - セル内で通常どおりカーソルが移動します。
  - セルの左右端に到達した状態で、さらに同じ方向に押した場合のみ、隣のアドレスへ移動します（端に当たった 1 回目では移動しません）。
- Up / Down: 同じ列で 16 バイト上／下へ移動します。
- Home / End: 行頭／行末へ移動します。

補足:
- セル移動直後は、入力しやすいように値全体が選択状態になります（上書きしやすい）。
- 文字入力は egui の通常動作（挿入／削除）に従います。ペーストも利用できます。

## 表示・追従

- Follow PC（PC 追従）:
  - 有効時は PC に基づくハイライトと自動スクロールが行われます。
  - Hex と Lst の切替時も、PC 行のハイライトが計算できたフレームで自動的に中央へスクロールします。
- リスティング更新:
  - メモリを書き換えた場合、対象スパンの逆アセンブルが再計算され、Hex リスティングが最新化されます。

## 適用時の注意

- 適用は一時停止（Pause）中に行われます（UI が内部で制御）。
- MMU などで書き込みが保護されている領域は反映されない場合があります。その場合は次回読み出しで差分が消えます。

## 既知の仕様

- ASCII 領域は読みやすさのための表示で、Hex 側の編集内容を反映してハイライトします。
- ペンディングは Hex セル単位で保持されます。Apply/Cancel でまとめて確定／破棄します。

## トラブルシュート

- 「上下・左右カーソルが効かない」
  - セルにフォーカスがあるかを確認してください。クリックで選択してから操作してください。
- 「隣のセルに移動しない」
  - 左右は “端に到達 → もう一度同方向キー” の 2 段階で移動します。端到達直後はセル内に留まります。
- 「Apply 後にまだ編集モードのまま」
  - 現在の実装では Apply 後に自動で編集モードを終了します（仕様）。
